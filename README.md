# Churn case

Predicts `avgang_6mnd` — whether a customer left in Jan–Jun 2026 — from the
2025-12-31 snapshot in `../teknisk_case_data`.

Findings and business reading: [`SUMMARY.md`](SUMMARY.md) (or `report/report.pdf`).
Results table: `outputs/metrics/model_comparison.csv`, written by `evaluate`
rather than transcribed by hand.

## Running

Python 3.11+. From this directory:

```bash
python -m pip install -r requirements.txt

python -m src.pipeline build-features   # clean, validate, build main.parquet + grouped split
python -m src.pipeline train            # the experiments listed in config.yaml
python -m src.pipeline evaluate         # comparison table and figures
python -m src.pipeline analyse          # descriptive tables and figures
python -m src.pipeline run-all          # all of the above, in order

python -m pytest                        # 30 tests
```

Everything is driven by `config.yaml` — seed, feature sets, model grids, k
values, the leakage column list, and which experiments run. No notebooks.

The embedding model downloads from Hugging Face on first use and is cached to
`outputs/features/`. Topic labelling calls an OpenAI-compatible endpoint
(`clusters.annotation.served`, configured for Ollama at `localhost:11434` with
`qwen3:8b`); if none is reachable it falls back to deterministic
term-frequency labels, so the pipeline runs without it. Labels are for
interpretation only and never reach a model.

## Code structure

```text
src/
  pipeline.py          CLI and stage wiring
  config.py            loads config.yaml, resolves output paths
  analysis.py          descriptive tables and figures (no model involved)
  data/
    load.py            read the four CSVs
    clean.py           deduplicate, normalize categories, repair implausible values
    validate.py        raw-file report, then hard asserts on the modelling table
  features/
    build.py           assemble the feature sets and cache them as parquet
    customers.py       customer attributes, log balances, structural-zero flags
    engagement.py      five engagement features, year-over-year to cancel season
    inquiries.py       contact counts, recency, channel mix
    text.py            TF-IDF vectorizer (fitted inside the model pipeline)
    embeddings.py      Qwen3 inquiry embeddings, cached and keyed by model+dim
    clusters.py        KMeans on training inquiries only, one share per topic
    annotate.py        LLM topic labels, with a term-frequency fallback
  models/
    split.py           grouped train/test split, keeps relation pairs together
    logistic.py        logistic regression pipeline
    catboost.py        CatBoost pipeline
    train.py           fit, score, persist model + metrics + predictions
  evaluation/
    metrics.py         PR-AUC and precision/recall/lift at k
    plots.py           precision-recall curve, precision/recall by capacity
    report.py          the model comparison table
tests/                 leakage, cleaning, engagement seasonality, clustering
report/                build.sh renders SUMMARY.md to report.pdf
```

Feature sets: `main` (23 structured features), `main_text` (`main` + TF-IDF),
`main_clusters` (`main` + embedding topic shares).

`outputs/` is written by the pipeline and is untracked apart from
`outputs/figures`, which the report embeds. Everything else - metrics tables,
parquet feature sets, fitted models, predictions and the split - is
regenerated by `run-all`.

## Rebuilding the report

```bash
./report/build.sh
```

Renders `SUMMARY.md` to `report/report.pdf` via pandoc and pdflatex, both of
which must be installed. `report/columns.lua` adds side-by-side columns, which
Markdown has no syntax for.
